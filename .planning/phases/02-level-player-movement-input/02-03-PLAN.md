INPUT (`js/input.js`, global `Input`) — intent only, never mutation (D-07). Hold `keys`, a null-prototype object mapping held physical key codes to true. Hold `mouseDX`, a running sum of raw horizontal mouse movement in pixels. Hold `locked`, a boolean mirroring pointer-lock state, and `canvas`, the element lock is requested on.
  - `Input.BINDINGS` is a data table mapping physical key codes to intent slots: `KeyW` forward positive, `KeyS` forward negative, `KeyA` strafe negative, `KeyD` strafe positive, `ArrowLeft` turn negative, `ArrowRight` turn positive, `ShiftLeft` and `ShiftRight` run. Use `event.code` (the physical key), never `event.key`, so the bindings survive non-QWERTY layouts and modifier combinations.
  - `Input.attach(canvas)` registers listeners: window `keydown` sets the code in `keys`, window `keyup` deletes it. A canvas `click` handler calls `Input.requestLock()`. A document `mousemove` handler adds `event.movementX` to `mouseDX` but ONLY when `document.pointerLockElement` is the attached canvas, read at event time.
  - `Input.requestLock()` calls the canvas's pointer-lock request preferring the unadjusted-movement option (Chromium honours it and delivers raw deltas; other browsers ignore the unknown option harmlessly), wrapped so both a synchronous throw and a rejected promise are caught and recorded rather than propagating.
  - `Input.intent` is ONE reused record `{forward, strafe, turn, run, mouseDX}` — never allocate per frame. `Input.readIntent()` recomputes the four numeric slots and the run boolean from `keys` by walking `BINDINGS`, copies `mouseDX` into the record, ZEROES `Input.mouseDX`, and returns the record. Draining on read is what guarantees a mouse delta is applied exactly once.
  - `Input.reset()` clears every held key and zeroes `mouseDX`.

TOP-DOWN VIEW (`js/topdown.js`, global `TopDown`) — the Phase 2 verification screen (D-09). Expose `TopDown.ENABLED` defaulting to true, the flag Phase 3 flips.
